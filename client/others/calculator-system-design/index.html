Architecture principle
Separation of concerns
Each component has ONE job. The display doesn't compute. The state doesn't render. This makes debugging, testing, and AI-assisted generation far cleaner.
Single source of truth
State is the single source of truth. The display always reads from state — it never maintains its own data. This prevents inconsistency between what's shown and what's stored.
Pure compute functions
The compute unit is a pure function — same inputs always return the same output, with no side effects. This concept scales from a calculator all the way to backend services.

The quality of your system design thinking directly determines the quality of AI-generated code. Vague prompts produce vague code. Precise architecture thinking produces usable implementation.

Weak vs strong prompts
Weak prompt

The AI receives a complete specification. The component boundaries, state shape, and edge cases are already decided. Output will match your architecture.

Does the compute unit work as a pure function?
▾
A pure function has no side effects — same input always gives the same output. This is critical for testability and correctness.
function compute(a, op, b) { a = parseFloat(a); b = parseFloat(b); if (op === '+') return a + b; if (op === '-') return a - b; if (op === '*') return a * b; if (op === '/') return b === 0 ? 'Error' : a / b; return a; }
✓ This is correct. The function reads no external state, modifies nothing outside itself, and handles the divide-by-zero edge case inline. It can be unit-tested independently.
✗
Is the state mutation controlled in one place?
▾
State should only change inside the handler function. If state is mutated in multiple places, bugs become very hard to trace.

Fix needed: All state.* writes should happen in one handler function. The render function should only READ from state, never write to it. This is the single-source-of-truth principle from Phase 2.

Does the equals key repeat the last operation when pressed twice?
▾
Real calculators repeat the last operation on double-equals. This requires storing lastOperator and lastOperand in state.

Fix: Before resetting, store state.lastOp = state.operator and state.lastOperand = state.operand2. On the next equals press, use these stored values to repeat the computation. This is the edge case you identified in Phase 1.
