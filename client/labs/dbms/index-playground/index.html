Step 3 · Behind the scenes

What MySQL does when you create an index

Next: search again →
CREATE INDEX idx_name ON students (name);
1Scan the tableCopy each row's name + id into the sort buffer.
2SortSort each full buffer, then merge the sorted runs.
3Build the tree, bottom-upFill leaf pages in order; each full page gets a pointer in the page above.

Same query, two very different jobs

Without an index

With idx_name

type: ref
2
pages opened
  • Root page → one leaf page → done.
  • The index is sorted, so MySQL knows where to look.
i

The price: every INSERT, UPDATE and DELETE must also update idx_name. So index the columns you search, not every column.

Toy data: 100 made-up students. Toy sizes: 50 entries per sort buffer, 10 entries per page. Real InnoDB pages are 16 KB by default.
