Three kinds of file, and every case your Java program has to survive.

  • A players file holding one line per person who has ever played.
  • A question file for every topic and level pairing, which the program only ever reads.
  • A results file for every topic and level pairing, which the program only ever adds to.
  • A name that has played before is recognised, not added twice.
  • A name carrying your separator mark is refused before it can corrupt a record.
  • A topic file with fewer than ten questions is reported, not padded with repeats.
  • A broken record in the middle of a question file is skipped, and the quiz still runs.
  • The clock running out ends the quiz and still saves the marks earned.
  • The first score for a pairing creates the results file instead of failing to open it.
  • Quit the program, run it again — every leaderboard is still there. That is the point.
